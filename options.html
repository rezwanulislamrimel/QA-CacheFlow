Required Permissions

This extension requests the minimum permissions needed. Here is exactly why each is required:

Required browsingData

Required to call chrome.browsingData.remove() which clears HTTP cache, Cache Storage, cookies, localStorage, IndexedDB, and service workers. Without this, no cleanup is possible.

Required tabs

Required to read the current tab's URL and hostname so cleanup can be scoped to the correct origin. Also needed to reload the tab after cleanup and to update the action badge when the active tab changes.

Required storage

Required to persist saved sites, cleanup history, preferences, and theme. Uses chrome.storage.local only — data never leaves the device.

Required activeTab

Allows reading the currently active tab without requiring broad host permissions. Granted only when the user explicitly interacts with the extension.

Optional cookies

Listed as an optional permission for future features (e.g., listing cookies for a domain). Cookie clearing is handled through browsingData which does not require this permission. Not currently requested at runtime.

🔒 No Host Permissions

This extension does not request <all_urls> or any host-match patterns. It uses activeTab which gives access only when the user explicitly invokes the extension. This minimizes the extension's privilege surface.

What Data We Store

All data is stored locally on your device using chrome.storage.local.

  • Saved sites: Name, domain, environment label, optional notes. No credentials.
  • Cleanup history: Domain name, timestamp, data types cleared. No page content.
  • Preferences: Theme, default time range, preserve-login toggle.

What We Never Collect

  • We never transmit any data to external servers.
  • We never read page content, form data, or credentials.
  • We never store full URLs or query strings in history.
  • We do not use analytics, tracking, or crash reporting.

Export & Delete Local Data

This removes all saved sites, history, and preferences. Cannot be undone.

Known API Limitations

  • HTTP Cache is origin-scoped, not truly domain-scoped. Clearing https://app.example.com does not clear https://static.example.com or resources from CDN origins. Resources loaded by the page from third-party origins are unaffected.
  • sessionStorage cannot be cleared via browsingData API. chrome.browsingData has no sessionStorage data type. sessionStorage is automatically discarded when the tab closes or navigates. This is an honest Chrome API limitation.
  • Cookie domain scoping may affect subdomains. A cookie with Domain=.example.com is shared across app.example.com, api.example.com, etc. Clearing cookies for one origin may sign the user out of other subdomains.
  • Localhost ports are separate origins. http://localhost:3000 and http://localhost:3001 are treated as completely separate origins. Data for each port must be cleared separately.
  • Hard reload is not the same as clearing cache. A hard reload (Ctrl+Shift+R) bypasses disk cache for the navigation request but still uses cached subresources. The extension's "Clear Cache & Reload" actually removes cached data before reloading.
  • Service worker caches. Service workers manage their own caches via the Cache API. Clearing Cache Storage via browsingData removes these caches. Clearing serviceWorkers unregisters the SW, which will re-register on the next page load and may re-populate its caches.
  • origins filter availability. The origins filter on chrome.browsingData was added in Chrome 74. On older or non-Chrome browsers, cleanup may fail. We never fall back to global clearing — instead we report the error honestly.
  • Shared browser caches. Some browser-managed caches (DNS cache, SSL session cache, HSTS cache) are not exposed by the browsingData API and cannot be cleared by this extension.
